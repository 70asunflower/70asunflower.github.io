# 2. SIMT：Single Instruction Multiple Threads

原文提到：

> SIMT, Single Instruction Multiple Threads.

SIMT 是 GPU 执行模型的核心。

---

## 2.1 什么是 SIMT？

SIMT 可以理解为：

> 多个线程在同一时间执行同一条指令，但每个线程可以操作不同数据。

例如：

```text
for each pixel:
    color = texture_lookup(...)
    color = lighting(...)
    write_framebuffer(color)
```

或者深度学习中：

```text
for each element in tensor:
    y[i] = activation(x[i])
```

很多线程同时做相似操作，但处理不同数据。

---

## 2.2 SIMT 和 SIMD 的关系

SIMT 与 SIMD 很像，但 SIMT 对程序员更友好。

粗略理解：

|模型|特点|
| ------------| ----------------------------------|
|SIMD|单指令多数据，通常显式向量寄存器|
|SIMT|单指令多线程，线程模型更通用|
|CPU vector|例如 AVX，向量长度固定|
|GPU SIMT|大量线程，由硬件调度|

在 NVIDIA GPU 中，线程通常以 **warp** 为单位执行，例如 32 个线程一组。

---

## 2.3 为什么 SIMT 适合高吞吐？

GPU 可以通过大量线程隐藏延迟。

例如：

- 一组线程等待内存；
- 另一组线程继续计算；
- 硬件快速切换 warp；
- 计算单元保持忙碌。

所以 GPU 的优势不是：

```text
让一个任务尽快完成
```

而是：

```text
让大量任务整体吞吐最大化
```

这与 AI 训练/推理非常契合。

# 6. 典型 GPU 服务器：CPU host + PCIe + GPUs

原文：

> A typical system includes a CPU host connected to accelerators via high-speed PCIe links.

典型 GPU 服务器结构：

```text
CPU host
   ↓ PCIe
GPU 0
GPU 1
GPU 2
GPU 3
...
```

PCIe 是 CPU 和 GPU 之间的通用高速 I/O 通道。

它负责：

- 主机控制；
- 内存访问；
- 设备初始化；
- 数据传输；
- DMA；
- 中断；
- 管理接口。

PCIe 的优点是通用、成熟、兼容性好。

但 PCIe 也有局限：

- 带宽低于专用 GPU-GPU 互连；
- 延迟高于片内互连；
- 多 GPU 通信可能受 PCIe topology 限制；
- 不适合所有大规模 collective communication。

因此 GPU 系统还需要更高速的 GPU-GPU 互连。

# 7. 为什么 GPU 系统需要多个网络？

原文说：

> Since GPUs can process trillions of operations per second, they require trillions of bits per second to balance the system, much more than the 100 Gbps or so provided by a standard server.

这句话说明了一个核心问题：

> 计算能力越强，对数据供给和网络带宽的要求越高。

```text

系统不平衡
GPU 利用率下降
```

所以 GPU 部署通常需要多个网络。

# 9. NVLink 为什么重要？

NVLink 是 GPU 系统中非常关键的互连。

---

## 9.1 PCIe 的不足

PCIe 虽然通用，但对于多 GPU 训练来说可能不够。

例如 8 个 GPU 如果都通过 PCIe 交换数据，可能出现：

- 带宽竞争；
- CPU/PCIe switch 瓶颈；
- 高延迟；
- collective communication 效率低；
- GPU 利用率下降。

---

## 9.2 NVLink 的优势

NVLink 提供：

- 更高带宽；
- 更低延迟；
- 更直接的 GPU-GPU 通信；
- 更适合 collective communication；
- 更适合 tensor parallel；
- 更适合多 GPU 内存共享。

因此现代 GPU 服务器通常会尽量让 GPU 之间通过 NVLink/NVSwitch 通信，而不是绕 PCIe。

# 10. CPU-GPU 高带宽路径：Grace-Hopper 架构

原文：

> Additionally, some GPUs, e.g., NVIDIA’s Grace-Hopper architecture, also feature a high-bandwidth path between the host CPU and the GPU, replacing the convenient but slower PCIe links previously used for that purpose.

这里提到 Grace-Hopper。

它代表一种趋势：

> CPU 和 GPU 之间不再只依赖 PCIe，而是使用更高带宽、更低延迟的专用互连。

---

## 10.1 为什么需要更高带宽 CPU-GPU 路径？

传统 PCIe 虽然方便，但在某些场景下会成为瓶颈。

例如：

- CPU 预处理数据后传给 GPU；
- GPU 访问主机内存；
- CPU/GPU 协同计算；
- 统一内存访问；
- 大规模 embedding；
- 数据加载；
- 推理 pipeline；
- 异构内存管理。

如果 CPU-GPU 带宽不足，会出现：

```text
GPU 等待 CPU 数据
或者 CPU 等待 GPU 结果
```

---

## 10.2 Grace-Hopper 的意义

Grace-Hopper 将 CPU 和 GPU 更紧密连接。

好处可能包括：

- 更高 CPU-GPU 带宽；
- 更低延迟；
- 更高效内存访问；
- 更统一内存模型；
- 减少数据拷贝；
- 提高异构计算效率。

这体现了现代 AI 系统的一个趋势：

> 不只是加速器之间要高速互连，CPU、GPU、内存、网络之间也要协同设计。

# 11. 多节点 GPU 训练：InfiniBand 和高速 Ethernet

原文：

> Beyond individual nodes, large-scale training often involves interconnecting multiple GPU-equipped system-nodes.

单节点 GPU 数量再多，也常常不够。

大模型训练需要跨节点。

---

## 11.1 为什么需要跨节点训练？

因为大模型需要：

- 更多参数；
- 更多 activation；
- 更多 gradient；
- 更多 optimizer state；
- 更大 batch；
- 更高吞吐；
- 更短训练时间。

单节点显存和算力有限，所以必须分布式训练。

常见并行方式包括：

|并行方式|作用|
| ----------------------| -----------------------------------|
|data parallelism|每个 GPU 处理不同 batch，同步梯度|
|tensor parallelism|把一个矩阵乘法切到多个 GPU|
|pipeline parallelism|把模型层切到不同 GPU|
|expert parallelism|MoE 中把 expert 分布到不同 GPU|
|sequence parallelism|沿序列维度切分|
|context parallelism|长上下文切分|

这些并行方式都依赖高速网络。

---

## 11.2 同步训练中的参数同步

原文：

> High-performance networks, such as InfiniBand and high-speed Ethernet, play a crucial role in facilitating fast parameter synchronization across distributed systems during synchronous training.

同步训练中，每个 step 后通常需要聚合梯度。

典型流程：

```text
每个 GPU 计算 forward
        ↓
计算 backward 得到 gradient
        ↓
all-reduce gradients
        ↓
每个 GPU 更新 parameters
        ↓
进入下一个 step
```

其中 `all-reduce` 是关键通信操作。

如果网络慢，就会出现：

```text
GPU 算得快
通信等得久
整体训练速度下降
```

所以网络带宽和延迟直接决定训练 goodput。

# 12. NCCL：NVIDIA Collective Communication Library

原文：

> Specialized software libraries, like NVIDIA Collective Communication Library NCCL, are further optimized for collective communication operations like all-reduce and all-gather, minimizing communication overhead and maximizing the utilization of these high-bandwidth networks.

NCCL 是 GPU 分布式训练中的关键软件库。

---

## 12.1 NCCL 做什么？

NCCL 优化 collective communication，例如：

- all-reduce；
- all-gather；
- reduce-scatter；
- broadcast；
- reduce；
- all-to-all；
- send/recv。

这些操作在分布式训练中非常常见。

---

## 12.2 为什么需要 NCCL？

因为 collective communication 很复杂。

它要考虑：

- GPU 拓扑；
- NVLink；
- PCIe；
- NVSwitch；
- InfiniBand；
- Ethernet；
- RDMA；
- 网络拥塞；
- 节点内/节点间路径；
- 消息大小；
- 算法选择；
- 带宽利用；
- 延迟。

NCCL 可以根据拓扑选择算法，例如：

- ring all-reduce；
- tree all-reduce；
- hierarchical all-reduce；
- node-local reduce；
- inter-node reduce。

目标是：

```text
最小化通信时间
最大化网络利用率
减少 GPU 等待
```

原文最后说：

> Successive GPU generations have consistently increased FLOPS, memory capacity and bandwidth, and networking capabilities. Additionally, investments in lower-precision numerics, from bf16 to fp8 and fp4, improve peak FLOPS and enable larger models.

GPU 的演进方向可以总结为四个方面。

---

## 14.1 更高 FLOPS

每代 GPU 通常提升：

- FP32；
- TF32；
- BF16；
- FP16；
- FP8；
- INT8；
- FP4；
- tensor/matrix 计算吞吐。

这使得单卡能处理更大模型或更高 batch。

---

## 14.2 更大内存容量和带宽

GPU 内存对 AI 极其关键。

提升内存可以：

- 装下更大模型；
- 支持更长上下文；
- 支持更大 batch；
- 减少 offload；
- 提高推理吞吐；
- 改善训练稳定性。

提升带宽可以：

- 更快喂计算单元；
- 降低 decode 瓶颈；
- 提高 embedding 性能；
- 减少内存等待。

---

## 14.3 更强网络能力

GPU 代际也提升：

- NVLink 带宽；
- NVSwitch 能力；
- PCIe 代际；
- InfiniBand 支持；
- RoCE/Ethernet 支持；
- RDMA；
- collective communication 硬件加速；
- 多节点扩展能力。

因为大模型训练越来越依赖通信效率。

---

## 14.4 更低精度数值

原文提到：

> from bf16 to fp8 and fp4.

低精度可以提高：

- peak FLOPS；
- 内存利用率；
- 带宽利用率；
- 能效；
- 推理吞吐。

但也带来挑战：

- 精度损失；
- 训练稳定性；
- outlier；
- scaling；
- 量化误差；
- 校准成本；
- 软件栈复杂度。

# 15. BF16、FP8、FP4 的直觉理解

---

## 15.1 BF16

BF16 保留 FP32 的 exponent 范围，减少 mantissa。

优点：

- 动态范围大；
- 训练稳定；
- 比 FP32 省带宽和算力；
- 适合 DNN 权重和梯度。

---

## 15.2 FP8

FP8 进一步降低位数。

常见思路是：

- 用更少 bit 表示 activation；
- 用更少 bit 表示 gradient；
- 配合 scaling factor；
- 在 tensor 或 block 级别缩放。

FP8 可以显著提高吞吐，但需要更精细的数值管理。

---

## 15.3 FP4

FP4 更激进，通常更适合：

- 推理；
- 权重量化；
- 特定模型；
- 经过量化训练或校准的 workload。

FP4 对精度和校准要求更高。

---

# 16. GPU 与 TPU 的对比

这一节可以和上一节 TPU 对照理解。

|维度|GPU|TPU|
| --------------------------| ---------------------------| ------------------------------|
|起源|图形处理|AI 张量处理|
|定位|通用并行 + AI 加速|AI 专用加速器系统|
|编程生态|CUDA、PyTorch、JAX 等广泛|XLA、JAX、TensorFlow 等|
|灵活性|很高|相对专用|
|节点内互连|NVLink/NVSwitch|ICI|
|跨节点互连|InfiniBand/Ethernet|ICI/OCS pod 网络|

|稀疏支持|稀疏 tensor core、软件库|SparseCore|
|低精度|BF16/FP8/FP4 等|BF16 先驱，bf8/bf4|
|系统形态|GPU server/rack/pod|TPU pod/supercomputer|
|优势|灵活、生态强、通用|专用系统集成、能效、pod 拓扑|

简单说：

```text
GPU 强在通用性和生态；
TPU 强在专用系统集成和 pod 级设计。
```

# 19. 可以用来检验理解的问题

---

## 问题 1：GPU 为什么适合深度学习？

因为深度学习有大量可并行计算，例如矩阵乘法、卷积、向量激活和梯度计算。

GPU 具有：

- 大量 SIMT 核心；
- 高内存带宽；
- 矩阵加速单元；
- CUDA 生态；
- 多 GPU 互连；
- 低精度计算支持。

这些特性使其非常适合 DNN 训练和推理。

---

## 问题 2：GP-GPU 和传统 GPU 的区别是什么？

传统 GPU 主要做图形处理，例如像素着色、顶点变换、光栅化。

GP-GPU 支持通用并行计算，例如：

- FP32/FP64 向量运算；
- 线性代数；
- 科学计算；
- 模拟；
- 机器学习。

---

## 问题 3：为什么 GPU 部署需要多个网络？

因为 GPU 计算吞吐极高，需要大量数据输入输出和跨节点通信。

通常需要：

1. CPU/管理网络；
2. GPU 外部数据/存储/跨机架网络；
3. 节点内 GPU-GPU 高速互连网络。

---

## 问题 4：NVLink 的作用是什么？

NVLink 提供节点内 GPU-GPU 高速互连。

它比 PCIe 更适合：

- 多 GPU 通信；
- tensor parallel；
- all-reduce；
- all-gather；
- 低延迟数据交换；
- 高带宽 collective communication。

---

## 问题 5：GPU 跨节点训练为什么依赖 InfiniBand 或高速 Ethernet？

因为大模型训练需要多节点参数同步。

同步训练中，梯度需要 all-reduce。

如果跨节点网络慢，GPU 会等待通信，训练吞吐下降。

---

## 问题 6：NCCL 为什么重要？

NCCL 优化 collective communication。

它能根据 GPU 拓扑和网络选择高效算法，减少通信开销，提高：

- all-reduce；
- all-gather；
- reduce-scatter；
- all-to-all；

等操作的效率。

---

## 问题 7：GPU 与 TPU 在互连上的主要区别是什么？

按原文语境：

- GPU 节点内常用 NVLink；
- GPU 跨节点/跨机架常用 InfiniBand 或高速 Ethernet；
- TPU 使用 ICI 和 OCS 构成 pod 级专用互连网络。

也就是说：

```text
GPU：节点内 NVLink + 跨节点 IB/Ethernet
TPU：pod 内 ICI/OCS 专用互连
```

# 20. 这一节可以整理成的精简笔记

```text
6.3.2.2 GPUs

1. 核心观点：
   GPU 是面向并行处理的专用处理器。
   它从图形加速器演化为通用并行计算平台，
   再通过矩阵乘引擎、低精度计算、NVLink、
   InfiniBand/Ethernet 和 NCCL 成为现代 AI 训练/推理核心系统。

2. GPU 的基本特征：
   - 单芯片包含大量 SIMT 核心；
   - 强调大规模并行和高吞吐；
   - 不优先优化单线程延迟；
   - 适合规则、数据并行、向量/矩阵计算；
   - 通过大量线程隐藏内存和调度延迟。

3. GPU 的历史演化：
   - 1990 年代：图形处理加速器；
   - 2006 年前后：GP-GPU 出现，支持通用 FP32/FP64 向量计算；
   - 2012 年：AlexNet 使用 GPU 训练 CNN，推动深度学习爆发；
   - 今天：通用 GPU 增加专用矩阵乘引擎，
     成为 AI 训练和推理的核心加速器。

4. 为什么 GPU 适合深度学习：
   - DNN 有大量矩阵乘法、卷积、向量激活和梯度计算；
   - GPU 的大规模并行结构适合这些操作；
   - 高内存带宽有助于喂饱计算单元；
   - CUDA/cuDNN/NCCL/PyTorch 等生态成熟；
   - GPU 比 ASIC 更灵活，能快速支持新模型。

5. 典型 GPU 服务器结构：
   - CPU host 通过 PCIe 连接 GPU；
   - PCIe 通用、成熟，但带宽和延迟不如专用 GPU-GPU 互连；
   - 单 GPU 不够，深度学习依赖 multi-GPU 和 multi-node 配置；
   - 系统需要平衡计算、内存、存储和网络带宽。

6. GPU 部署中的三个网络：
   1）常规服务器网络：
       给 CPU host 使用，带宽通常最低，
       负责管理、控制、普通网络流量；
   2）GPU 外部数据网络：
       NIC 通常通过 PCIe 连接 GPU，
       提供到存储或其他 GPU 机架的带宽，
       常用 Ethernet/InfiniBand/RoCE；
   3）节点内 GPU-GPU 专用互连：
       例如 NVLink，
       提供高带宽、低延迟 GPU-to-GPU 通信，
       作用类似 TPU 的 ICI。

7. GPU 与 TPU 网络差异：
   - GPU 节点内常用 NVLink/NVSwitch；
   - GPU 跨节点/跨机架通常依赖 InfiniBand 或高速 Ethernet；
   - TPU 使用 ICI 和 OCS 构成 pod 级专用互连；
   - 因此 GPU 集群更依赖通用高性能网络和 NCCL。

8. CPU-GPU 高带宽路径：
   - 传统 CPU-GPU 主要依赖 PCIe；
   - Grace-Hopper 等架构提供更高带宽 CPU-GPU 路径；
   - 目的是减少 PCIe 瓶颈，提高异构计算效率；
   - 有利于 CPU/GPU 协同、内存访问和数据搬运优化。

9. 多节点训练：
   - 大模型训练需要跨节点；
   - 同步训练需要快速参数同步；
   - all-reduce 是关键通信操作；
   - 网络带宽和延迟直接影响训练 goodput；
   - InfiniBand 和高速 Ethernet 是常见高性能网络。

10. NCCL：
   - NVIDIA Collective Communication Library；
   - 优化 all-reduce、all-gather、reduce-scatter、all-to-all 等；
   - 能感知 NVLink、PCIe、InfiniBand、Ethernet 拓扑；
   - 通过 ring/tree/hierarchical 算法减少通信开销；
   - 是 GPU 分布式训练软件栈的关键组件。

11. GPU rack 和 pod：
   - 大规模 GPU 训练常由多个 GPU 节点组成 pod；
   - 机架中可能有 2U server tray 和 8U GPU tray；
   - CPU tray 负责主机、存储、网络和管理；
   - GPU tray 负责高密度 GPU 计算和 GPU-GPU 互连；
   - pod 通过高速网络连接，形成训练大模型的并行系统。

12. GPU 代际演进方向：
   - 提高 peak FLOPS；
   - 提高内存容量和带宽；
   - 提高网络能力；
   - 支持更低精度数值；
   - 优化 collective communication；
   - 提高每瓦性能和系统级 goodput。

13. 低精度数值：
   - bf16 保留 FP32 exponent 范围，适合 DNN 训练；
   - fp8 进一步提高吞吐，但需要 scaling 和数值管理；
   - fp4 更激进，常用于推理或经过量化的模型；
   - 低精度提高 peak FLOPS 和内存效率，
     但也带来精度、稳定性和软件复杂度挑战。

14. 总结：
   GPU 的成功不是单卡算力，
   而是通用并行架构、矩阵加速单元、高带宽内存、
   NVLink、InfiniBand/Ethernet、NCCL、
   CUDA 生态和低精度计算共同构成的系统优势。
   理解 GPU 必须从单卡、节点、机架、pod
   和软件栈多个层面同时理解。
```

# 21. 如果考试或讨论中要回答这一节，可以这样说

> 6.3.2.2 节讨论 GPU 如何从图形处理器演化为现代 AI 训练和推理的核心加速器。GPU 最初在 1990 年代用于图形处理，因为图形任务天然适合大规模并行。2006 年前后，GPU 分化出通用 GPU，即 GP-GPU，开始支持 FP32 和 FP64 向量计算，进入高性能计算市场。2012 年 AlexNet 使用 GPU 训练 CNN，在图像识别上取得突破，证明 GPU 可以显著加速神经网络训练。今天的 GPU 在通用并行能力之外，还加入了专用矩阵乘引擎，例如 tensor core，因此成为深度学习系统的核心。
>
> GPU 的基本架构特点是 SIMT，即单指令多线程。每个 GPU 芯片包含大量 SIMT 核心，通过大规模并行获得高吞吐。与 CPU 优先优化单线程延迟不同，GPU 更适合规则、数据并行、矩阵和向量计算。深度学习中大量操作，例如矩阵乘法、卷积、激活、归一化和梯度计算，都非常适合 GPU。
>
> 在实际部署中，GPU 深度学习系统依赖多节点配置。典型服务器由 CPU host 通过 PCIe 连接多个 GPU。PCIe 通用且成熟，但带宽和延迟不足以满足多 GPU 高速通信需求，因此 GPU 系统通常包含多个网络。第一个网络是常规服务器网络，给 CPU 使用，带宽通常最低。第二个网络是 GPU 外部数据网络，NIC 通过 PCIe 连接 GPU，用于访问存储或连接其他 GPU 机架。第三个网络是节点内 GPU-GPU 专用互连，例如 NVIDIA NVLink，它提供高带宽、低延迟的 GPU 间通信，作用类似 TPU 的 ICI。
>
> 一些新架构，例如 NVIDIA Grace-Hopper，还提供 CPU 和 GPU 之间的高带宽路径，以替代较慢的 PCIe，提高异构计算效率。 beyond individual nodes，大规模训练需要连接多个 GPU 节点。InfiniBand 和高速 Ethernet 在同步训练中非常重要，因为它们支持快速参数同步。NCCL 等软件库优化 all-reduce、all-gather 等 collective communication 操作，可以根据 NVLink、PCIe 和网络拓扑选择高效算法，减少通信开销，提高网络利用率。
>
> 在机架和 pod 层面，GPU 训练系统可能由 2U server tray 和 8U GPU tray 组成，多个机架通过高速网络构成 GPU pod。GPU 的代际演进不仅提高 peak FLOPS，还提高内存容量、内存带宽和网络能力。同时，低精度数值格式从 bf16 发展到 fp8、fp4，提高了峰值算力和模型部署效率，但也带来精度、稳定性和量化复杂度方面的挑战。
>
> 总体而言，GPU 的成功来自系统级优势：通用并行架构、矩阵加速单元、高带宽内存、NVLink 节点内互连、InfiniBand/Ethernet 跨节点网络、NCCL collective communication、CUDA 生态和低精度计算。理解 GPU 不能只看单卡 FLOPS，而要看它在节点、机架、pod 和软件栈中的整体吞吐、通信效率和 goodput。
