## 选刊与选会：从候选集到录用的完整实操指南

这篇要解决的是一个很具体的问题：手上有（或即将有）一份工作，它应该去哪里，以及提交之后会发生什么。

内容分五部分：建立三个基本判断；用四层过滤筛出候选；期刊的投递与迭代；会议的完整流程（包括 rebuttal、可复现包审查、双盲具体怎么做）；以及分领域的具体建议。末尾的附录 A 针对 AI Infra、计算机体系结构与集成电路方向给出具体刊物与会议清单。

不熟悉的术语可先看附录 B。

文中涉及的分区、周期、费用和会议制度均为量级参考，使用时应以官方页面和本单位当年文件为准。

> 本版核查时间：2026 年 7 月。

---

## 第一部分：先建立三个基本判断

### 1. 选刊是逐层淘汰，不是打分排序

候选刊物的评估因素看似很多（方向、等级、周期、录用率、费用、声誉），但它们不是平行的，而是有先后的：

```
第一层  硬约束      不满足就删行，没有商量余地
第二层  时间预算    周期超出你的截止日就删行
第三层  质量匹配    贡献类型与载体定位是否对应
第四层  成本与偏好  在前三层的幸存者里排序
```

这个顺序很重要。常见的浪费是花一下午比较两本刊的影响因子与版面费，而它们其中一本的 scope 根本不收你这类题目，另一本的周期已经超过你的送审时间。

### 2. 选刊的时机是立项时，不是投稿前

目标载体一旦定下，下面这些事就同时定下了：

|被反向决定的事|具体差别|
| ----------------------| ------------------------------------------------------|
|对比基线的数量与新旧|顶刊顶会要求含近两年最强方法；三四区可能比经典方法就够|
|实验规模与平台|系统类会议要求真实部署；部分期刊接受仿真结果|
|篇幅与图表密度|双栏八页和单栏二十页，叙事密度差几倍|
|是否需要开源与可复现包|系统类顶会普遍设有可复现审查环节|
|预印本能不能发、何时发|双盲会议可能限制审稿期间的公开行为|
|测量数据要记到什么程度|系统类审稿人会要求硬件型号、版本、重复次数、方差|

所以选刊应该有两个时间点。**立项时**定三到五本候选，并按其中最严的要求设计实验。**动笔前**定首投目标与备选序列，并按首投目标的模板排版。

写完再选的典型代价：篇幅压缩或扩写、补做对比实验、图表重绘、模板重排，两到六周。更麻烦的是有些事补不了：测量时没记环境细节，现在已经重现不了当时的条件。

### 3. 选刊就是选审稿人

一本刊、一个会，背后就是一个固定的人群。他们决定三件事：什么算贡献，什么算致命问题，哪些对比实验不能省。

怎么看出这个人群是谁：翻该刊（或该会）近两年与你题目相近的五六篇论文，看它们的相关工作章节默认引用哪一批人。那批人就是你的潜在审稿人，他们的工作就是你必须对比的基线。如果你的相关工作章节里一个都没提，审稿人会认为你不了解这个领域。

一个直接推论：同一份工作投往不同社区，需要重写叙事，不是换个模板。同一组数据，在算法社区要围绕指标提升写，在系统社区要围绕设计权衡与开销拆解写，在建模社区要围绕问题形式化写。

## 第二部分：四层过滤

### 第一层：硬约束

本层全部是是非判断。一条不过，后面三层就不必看。

#### 制度认定

要看的文件是三类：培养方案、学位授予细则、科研成果认定办法。需要确认的具体项：

- 认中科院分区还是 JCR 分区
- 认大类还是小类。同一本刊两个结果可能差整整一档
- 认哪一年的分区表：投稿年、录用年，还是见刊年
- 是否认完全开放获取期刊
- 是否认会议论文，认到 CCF 哪一档
- 是否排除特定出版商或预警名单刊物
- 是否要求本单位为第一署名单位
- 是否要求导师为通讯作者
- 是否有共同第一作者的认定限制

联合培养、联合实验室、企业实习期间产出的工作，署名单位归属要提前问清楚。这不是客气不客气的问题，而是一篇论文能不能算毕业成果的问题，而且只能在投稿前解决。

还有一个容易漏的风险点：分区表年份。如果一本刊今年二区、明年掉到三区，而学校按见刊年认定，跳年发表就有风险。所以要查该刊近三年的分区轨迹，不只查当年。

#### 方向匹配

三个递进的检查：

1. 官网 Aims & Scope 是否覆盖你的题目（注意这段文字往往写得很宽，参考价值有限）
2. 近两三年目录中是否真的有同类题目（比上一条可靠得多）
3. 你的参考文献里有几篇来自这本刊（最可靠）

方向不符是直接退稿的首要原因，而且成本完全沉没：没有审稿意见，只消耗了两到四周。

#### 收录状态

到 Master Journal List 查该刊当前是否仍在 SCIE 收录列表内。两个需要谨慎的情况：刚被收录两三年的新刊，被移出的概率高于老刊；投稿时在列、发表时已被移出，认定上往往出现争议。

#### 合规与伦理

要确认的事：不在《中国科学院国际期刊预警名单》内；不是掠夺性期刊；预印本政策与你已有的公开行为兼容；双盲要求与你的宣传计划兼容；AI 使用披露政策已读过。

掠夺性期刊的典型信号：

|信号|为何可疑|
| ------------------------------------------| ----------------------------------------|
|群发约稿邮件，称呼与你身份不符|正常刊物不需要拉稿，也不会把研一叫成教授|
|承诺一两周录用|真实审稿不可能这么快|
|开放获取费与同类刊物明显偏离|收入模式依赖发文量|
|编委名单无法溯源|可能盗用他人名义|
|宣称 SCI 收录但 Master Journal List 查不到|直接说谎|
|刊名在知名刊名上叠加冗余修饰词|刻意碰新手的识别盲区|

验证渠道按优先级：Master Journal List（收录事实）、DOAJ（合规开放获取白名单）、中科院预警名单（与国内认定直接相关）。Beall's List 原作者已于 2017 年停止维护，现存版本为匿名镜像，只能作辅助参考。

### 第二层：时间预算

期刊投稿通常不能一稿多投，因此候选序列是串行的：前一站结束后，才能进入下一站。真正需要估计的不是单一的“审稿周期”，而是从投稿到最终可用成果的日历时间。

可以用一个简化模型做情景分析：

```
E[T] = T₁ + (1-p₁)·T₂ + (1-p₁)(1-p₂)·T₃ + ...
```

其中，`pᵢ` 是在当前稿件质量和方向匹配下的粗略录用可能性，`Tᵢ` 应包含首轮决定、修改轮和最终决定，而不只是官网公布的 first decision。两者都无法精确知道，所以更适合分别代入乐观、基准、悲观三组估计，观察投递顺序是否改变。

例如，某候选高价值但周期长，另一候选匹配度更高且周期短。时间充裕时，可以承受前者失败的成本；如果毕业送审只剩半年，首要目标就应改为降低无法按时获得成果的风险。模型的作用不是算出一个漂亮的小数，而是让每次尝试所占用的日历时间变得可见。

#### 怎么估周期

三个数据源可以交叉使用：

**一、从已发表论文反推。** 下载该刊近期二十篇左右的论文，记录 Received、Revised、Accepted 日期并取中位数。需要注意，公开日期只覆盖最终发表者，天然忽略被拒稿件，因此仍有幸存者偏差。

**二、官网指标。** 有些期刊公布 median time to first decision。它通常只反映首轮，可能还包含很快结束的 desk reject，不能直接当作录用周期。

**三、众包平台。** LetPub 等平台适合了解量级与异常情况，但样本自选择明显，不宜把“平均周期”或“录用率”当作个人概率。

录用率是总体基准率，不是某篇具体稿件的录用概率。方向匹配、实验完整度、写作质量和编辑优先级都会改变结果，而且多数期刊并不公开完整统计。

#### 从硬日期倒推

从送审、申博、评奖或求职等硬日期向前预留：

- 录用到在线发表的时间
- 在线发表到正式卷期或数据库入库的滞后
- 每轮修改与补实验的时间
- 被拒后消化意见、重排格式和改投的时间

如果时间不足，应优先缩小候选范围、选择周期更可控的载体，或者调整成果形式。Letter、会议或快速通道是否合适，仍取决于工作类型和具体规则，不能只因为“快”就选。

### 第三层：质量匹配

先给自己的贡献分类，再找对应的载体。定位错了比档次选错更麻烦。

|贡献类型|典型形态|适配载体|审稿人的第一个问题|
| --------------| ------------------------------------------| ------------------------| ----------------------------|
|新问题|提出并形式化一个此前未被讨论的问题|顶刊、顶会正文|这个问题真实存在吗|
|新方法|在已有问题上取得可重复的显著改进|主流期刊、领域会议|比最强基线好多少|
|新系统|完整实现并端到端评测|系统类会议|能复现吗，开销拆解清楚吗|
|新测量|在新平台或新规模上的系统性测量与反直觉发现|测量类会议与期刊|测量方法严谨吗，结论能泛化吗|
|新数据集或基准|数据、标注、评测协议|数据集专刊、会议数据集轨|能持续维护吗|
|单点新颖结果|结论清晰但体系不完整|Letter、Short Paper|值得快速发布吗|
|系统梳理|领域综述|综述刊、受邀稿|有无独到的分类法|

最常见的错配是把“新测量”当“新方法”投。工作本身的价值是测出了别人测不了的东西，但因为叙事包装成方法创新，被“创新性不足”拒掉。正确的应对是换叙事、换载体，而不是降档。

自评档次的三个信号：

1. 对比实验是否包含近两年的最强方法，而不是只比经典方法
2. 提升幅度是否明显超过多次重复实验的波动范围
3. 结论是否在不止一个数据集、平台或规模上成立

三条都满足，才谈冲高档。满足两条，投匹配档。只满足一条，考虑拆成 Letter 或补实验。

### 第四层：成本与偏好

前三层的幸存者里再比：

- **开放获取费（APC）** ：完全开放期刊普遍在一千五百到四千美元区间，高影响力刊物可超六千；传统订阅制期刊可为零
- **超页费**：期刊与会议普遍设页数上限，超出部分按页收费，典型在每页一百多到三百美元
- **彩图费**：部分传统期刊仍对印刷版彩图收费
- **转投便利性**：同一出版商内部转投可携带审稿意见，能省一轮周期
- **编辑响应速度**：可从学长经验与公开讨论中得知

费用必须在投稿前与导师确认经费渠道。已经录用但无力付 APC 是真实发生的困境，而且几乎无法补救。

### 候选集从哪里来

四条信息通道，建议都过一遍：

1. **自己参考文献的刊物分布。** 把参考文献按载体计数，出现三次以上的就是强候选。这是最准的信号，因为它直接反映学术对话发生在哪里。
2. **选刊工具。** Elsevier Journal Finder、IEEE Publication Recommender、Springer Journal Suggester、Wiley Journal Finder、LetPub 选刊工具。注意出版商自家工具只推自家刊物，存在结构性偏差，应并行用多家。
3. **目标会议历年录用列表。** 找与你题目相近的论文，再查它们后续的期刊扩展版发在哪里。
4. **反向引用查询。** 找到你所依赖的那两三篇核心工作，在 Google Scholar 看引用它们的后续论文都发在哪里。这能找到工具推荐不出来的、小而精准的刊物。

## 第三部分：期刊的投递与迭代

### 为什么不用“冲稳保”

冲稳保是从高考志愿借来的说法，但两者机制不同。平行志愿是同时投递、一次录取；期刊是串行投递，每次失败花掉的是两到六个月的日历时间。三档分法只告诉你“投什么水平”，但不告诉你“按什么顺序投”，而后者才是真正影响结果的变量。

改成按两个量排序：估计录用概率、周期长度。三种情形导出三种不同策略：

|情形|目标|顺序策略|
| ------------| ----------------| ----------------------------------------------------------------------------------|
|剩余一年以上|押档次|先投低概率高价值刊。失败成本仅为周期，而高档刊的审稿意见质量明显更高，本身就是收益|
|剩余半年内|保录用|直接选高概率短周期刊，不尝试高档|
|中间|在约束内兼顾价值|在价值、匹配度相近且确实准备尝试的候选中，较长周期的刊物不宜放得太后|

最后一条反直觉。人的直觉是“先拉个安全的到手”或“把顶刊留到最后再试一把”，但周期最长的刊占用的日历时间最多，排得越晚就越可能因时间不够而永远没机会投。如果一本周期较长的刊物确实值得尝试，就不宜把它拖到时间窗口的末端。

另一个常被忽视的约束：同子领域的审稿人池高度重叠。原稿不改直接改投下一家，很可能撞上同一位审稿人，对方会认出稿子并直接重申原意见。所以每次改投前至少要实质回应上一轮的主要意见。

### 投稿系统里的状态到底是什么意思

投完之后你会反复刷投稿系统。各个状态的真实含义：

|状态|含义|正常停留时长|
| -----------------------------| ------------------------------------------| ------------|
|Submitted to Journal|刚提交，等编辑部形式审查|几天|
|With Editor / Editor Assigned|主编正在初审或分派副编辑|一到三周|
|Reviewers Invited|正在邀请审稿人（常需邀请十多位才凑齐三位）|两周到两个月|
|Under Review|审稿人已接受并在审|一到三个月|
|Required Reviews Completed|意见已齐，等编辑汇总|几天到两周|
|Decision in Process|编辑正在写决定|几天|
|Revise / Major Revision|进入修改阶段|看给定期限|
|Accepted|录用，等排版校样|—|

两个实用判断。**卡在 Reviewers Invited 很久不是坏事也不是好事**，只说明邀请不顺利，这在小领域很常见。 **“Under Review”很快变回“With Editor”并不一定是拒稿**，也可能是某位审稿人退出、编辑要重新邀请。

什么时候可以写信催（叫 inquiry 或 status request）：超过该刊官网声称周期的一倍以上，且状态三个月未变。信要短、客气、只问进度，不要催结果。频繁催促无助于加速，因为瓶颈在无偿的审稿人那里。

### 拒稿诊断表

拒稿不是一个事件，而是七种不同的信号。误诊会导致错误的下一步。

|结果|真实信号|下一步|
| ----------------------------| --------------------------------| --------------------------------------------------------|
|一到三周就退稿，理由提 scope|选刊错了，不是论文错了|换刊，内容几乎不必改，重写 Cover Letter|
|退稿理由为格式、查重、语言|投稿准备不合格|修格式、降重复率、送润色，可重新投同一本|
|外审后拒，意见集中在同一处|论文有一个明确的结构性缺陷|补那一处，然后仍可投同档|
|外审后拒，意见分散且互相矛盾|定位不清，审稿人没看懂你解决什么|重写引言与贡献陈述，而不是逐条补实验|
|Reject and Resubmit|编辑认可价值，但要求实质补充|通常值得做，重投成功率高于全新投稿|
|编辑建议转投姊妹刊|价值低于本刊但高于姊妹刊门槛|可接受（省一轮周期）或拒绝自主改投，先查姊妹刊分区与 APC|
|Major Revision|通常已过半|逐条回应，按时提交|

把直接退稿归因为“论文不行”是最常见的误判，直接后果是无谓降档。区分方法很简单：没有外审意见时，desk reject 通常不足以判断论文质量，因为编辑可能仅依据方向、篇幅、格式或优先级作出决定。

还有一个统计事实值得知道：同一篇稿子，两位审稿人给出相反推荐是常见现象而不是异常。单次拒稿的信息量比想象的低得多。

### 修改稿怎么写回应信

收到大修后，需要提交三份东西：修改后的稿件、标记修改的稿件（常用彩色或修订模式）、逐条回应信（response letter）。回应信往往比改稿本身更影响结果，因为审稿人二轮主要看它。

推荐的固定结构：

```
致编辑的一段话：感谢、概述主要改动（三到五条）

Reviewer 1
  Comment 1.1：原文照抄审稿意见
  Response：回应
  Changes：已在第 X 页第 Y 节 / 图 Z 修改，并摘引修改后的原文
  
  Comment 1.2 ...

Reviewer 2 ...
```

四条实用原则：

**逐条回应，一条不漏。** 即使是你认为无关的意见，也要写一句。漏回一条会被读作不尊重。

**先说改了什么，再说为什么。** 审稿人想知道的是结果，不是你的思考过程。把修改后的原文摘引进回应信，让他不必去稿件里翻。

**不同意也可以，但要给证据。** 写“我们理解这个关切，但在这个场景下……因此我们保持原方案，并在限制条件一节补充了说明”，而不是直接驳回。审稿人并不要求你全部服从，但要求你认真处理。

**不要情绪化。** 即使审稿意见写得很不客气，回应也保持平静。一句带刺的话可能直接换来一个拒稿。

如果两位审稿人意见相反（例如一位要求简化、一位要求展开），写清楚冲突何在，说明你的权衡选择，必要时请编辑裁定。这是正当做法。

### 红线

以下行为的后果不是拒稿，而是学术不端记录：

- **一稿多投。** 只有前一家给出正式拒稿、或你已确认撤回稿件后，才能投下一家。
- **会议扩展稿未声明。** 会议论文扩展投期刊是普遍允许的，但需同时满足两个条件：有可辨识的实质新增；引用会议版，并在 Cover Letter 与正文中说明两版差异。是否存在明确比例，以目标期刊政策为准。
- **切香肠式拆分。** 把一份完整工作拆成多篇低信息量论文，既损声誉也降引用。自检方法：如果两篇的贡献陈述能互换，它们就应该是一篇。
- **未经同意的署名变更**，包括添加未参与工作的作者。
- **AI 生成内容未披露。** 多数出版商现已要求声明 AI 工具的使用范围，且一致规定 AI 不能作为作者。
- **投稿到预警名单或掠夺性期刊。** 即使录用也可能不被认定，而且稿件已无法撕回重投。

## 第四部分：会议投稿的完整流程

在体系结构、操作系统、机器学习、网络和安全等计算机分支中，重要工作经常首先发表在会议上。前面的四层筛选仍然适用，但会议有一套由截止日驱动的流程。

|维度|期刊|会议|
| ----------| ----------------------------| ----------------------------------------------------|
|时间结构|多数可随时投稿，周期弹性较大|通常有固定截止日，错过要等下一轮|
|评审结构|可能经历多轮修改|多数在一个评审周期内决定，部分会议允许作者回应或修改|
|评价依据|期刊定位、分区与社区声誉|具体会议的社区声誉、选题范围与评审制度|
|录用后工作|校样、版权与出版|定稿、注册、报告，部分会议还有可复现包审查|

因此，会议投稿最好按“投稿前—评审中—录用后”的顺序理解。Rebuttal、meta-review、camera-ready 和 artifact evaluation 都只是这条流程中的不同环节。

### 1. 投稿前：截止日、摘要注册与双盲

#### 先确认两个截止日

部分会议会把摘要注册与正文提交分开：

- **Abstract registration deadline**：先登记标题、摘要、作者和主题，用于检查冲突并分配审稿人
- **Full paper deadline**：提交完整正文和规定的附件

摘要注册往往比正文截止早几天到一周。有些系统允许注册后修改标题和摘要，有些限制较严；没有按时注册，可能无法提交正文。年度日历里应同时记录这两个日期，而不是只记正文截止日。

#### 双盲不是删掉作者名字就结束

许多计算机会议采用双盲评审。常见处理包括：

- 正文不显示作者和单位，致谢、基金号通常留到定稿阶段
- 自引用保持第三人称，不写“在我们之前的工作中”
- 代码和数据使用会议允许的匿名链接或匿名仓库
- 检查 PDF、图片、附件和仓库提交记录是否泄露身份
- 在发布预印本或社交平台宣传前，核对当年的双盲与静默期政策

不同会议对已经存在的 arXiv、公开代码和学位论文处理不同。不要根据往年经验推断本届规则；直接查看当年的 Call for Papers、FAQ 和匿名政策。

### 2. 从投稿到开会：一条完整时间线

下面是一条典型的系统类会议流程，只用于理解先后关系，具体天数以当届通知为准：

```
正文截止前 7 天左右   摘要注册（如会议要求）
正文截止日            提交论文、附件和利益冲突信息
截止后数周            分配领域主席与审稿人，进入外部评审
截止后约 2—3 个月     审稿意见与评分公布
随后几天到一周        作者回应（author response / rebuttal，如有）
回应结束后            审稿人讨论，领域主席形成 meta-review
通知日                 Accept / Reject / Conditional Accept 等决定
录用后数周            Camera-ready、版权、注册和必要修改
之后或并行进行         Artifact evaluation（如有）
会议举行               口头报告、Poster、Demo 或其他展示
```

这条时间线说明了两个容易忽略的事实：第一，作者回应位于外部评审和程序委员会讨论之间；第二，收到录用通知后仍有定稿、注册、可复现包和报告准备等工作。

### 3. 评审阶段：Reviews、作者回应与录用决定

#### 审稿意见里通常有什么

会议审稿结果可能包含：

- 对论文贡献与优点的概括
- 关于正确性、新颖性、实验充分性和表达质量的意见
- 推荐分，例如 strong accept、weak accept、weak reject、strong reject
- 审稿人的信心度或专业熟悉程度
- 领域主席或元审稿人的总结意见

分数不能脱离理由单独解读。低分、低信心度不一定容易改变；高分也不代表已经录用。更有信息量的是审稿人反复提到的关键问题，以及这些问题能否通过原稿内容或可核验事实澄清。

#### 作者回应：澄清审稿意见，而不是重写论文

审稿意见公布后，一些会议会开放一个短暂的作者回应阶段，通常称为 **author response** 或 **rebuttal**。它位于外部评审和程序委员会讨论之间，作用是澄清事实误读、回答影响结论的关键疑问，并帮助委员会判断审稿意见是否足以影响录用决定。

传统流程通常只允许提交回应文字，不允许替换完整论文；也有会议采用 revision 或滚动评审，允许作者提交修改版。字数、能否附图、能否报告补充实验、审稿人是否可以改分，都要以当届作者通知为准。

##### 哪些意见优先回应

|意见类型|例子|推荐处理|
| ------------------| --------------------------------| ------------------------------------------------------|
|事实误读|“没有比较 X”，但正文已经比较|指出具体节号、图号和结果|
|可由原稿澄清|审稿人误解了假设、符号或适用范围|用简短定义和原文位置澄清|
|影响结论的关键质疑|正确性、基线公平性、泛化范围|优先回应，给出可核验的证据|
|需要补充实验|要求换平台、扩大规模或增加基线|先核对规则；允许时报告有限结果，否则说明限制并收窄主张|
|方法路线分歧|“为什么不用 Y”|说明设计目标和权衡，不把研究偏好争论成对错|
|写作与排版|图太小、符号不一致|简要说明会在允许修改的版本中处理|

篇幅优先留给可能改变录用判断、并且能够清楚澄清的问题。多位审稿人共同提出的关切可以合并放在前面，再处理单个审稿人的问题。

##### 一个简洁的组织方式

```
开头：感谢，并列出本次回应的两个到三个核心问题

Q1（多位审稿人的共同关切）
  结论 → 证据或原文位置 → 若录用将如何改写

Q2 ...

R1（某位审稿人的单独问题）
  简短回应

末尾：按规则允许的修改承诺清单
```

##### 常见错误

1. **语气对抗。** 把“审稿人没有读懂”改成“原稿表达不够清楚，相关内容位于……”。
2. **只有承诺，没有证据。** 无法提供结果时，应诚实说明限制并适当收窄结论。
3. **平均分配篇幅。** 排版问题不应挤占正确性和实验有效性问题的空间。
4. **临时引入新的贡献主线。** 这会让原稿显得定位不清。
5. **忽略字数与格式限制。** 系统可能直接截断超出的内容。
6. **把回应写成辩论赛。** 目标是帮助委员会判断，不是逐句证明审稿人错了。

短窗口内通常做不完大规模实验。更合理的准备方式是在投稿前列出三到五个最可能被质疑的点，检查稳健性分析、消融实验和基线公平性是否足以回答。这样做首先是改善原稿，其次才是为作者回应留有余量。

#### PC 讨论与 Meta-review

作者回应结束后，审稿人、领域主席或程序委员会会继续讨论。审稿人可能调整评分，也可能维持原判断。领域主席通常会综合原稿、评审意见和作者回应，形成 meta-review。

Meta-review 的作用是解释最终决定，而不是简单重复审稿意见。被拒时，它通常比任何一条单独意见更适合作为下一版的修改入口；被录用或有条件录用时，其中列出的必改项应优先处理。

#### 通知结果之后怎么判断下一步

- **Accept**：进入定稿、注册和报告准备阶段
- **Conditional Accept / Accept with Revision**：完成指定修改后才能最终录用，可能由 shepherd 监督
- **Reject**：结合 meta-review 判断问题属于贡献不足、实验缺口、定位不清还是载体不匹配
- **可转入 Poster、Short Paper 或其他轨道**：先判断这种发表形态是否影响后续扩展，再决定是否接受

会议拒稿后通常可以投往下一轮或其他会议，但应先实质回应主要意见。相邻会议的审稿人池可能重叠，原稿不改直接转投既浪费反馈，也可能再次遇到同样的问题。

### 4. 录用之后：定稿、Artifact 与报告

#### Camera-ready 与 Shepherding

Camera-ready 是录用后的最终版本。作者需要按规定修改正文、补回身份与致谢、完成版权手续并符合模板。它不是自由重写阶段：新增内容、页数和修改范围通常受限。

部分会议采用 **shepherding**：指定一位领域主席或审稿人检查必改项。此时应把 meta-review 中的要求逐条映射到最终修改，避免只交一份“看起来更完整”的新版。

#### 可复现包审查（Artifact Evaluation）

许多系统类会议设有独立的 artifact track。作者提交代码、数据、脚本和说明，由审查员检查材料是否可获得、能否运行，以及能否支持论文结果。它与论文录用有时相互独立，有时是录用后的可选环节。

以 ACM 常见体系为例，可能出现：

- **Artifacts Available**：材料已在公开、持久的存档中提供
- **Artifacts Evaluated – Functional**：材料完整，主要功能可以运行
- **Artifacts Evaluated – Reusable**：文档、结构和许可足以支持复用
- **Results Reproduced**：使用作者提供的材料得到主要结果
- **Results Replicated**：使用独立实现或材料得到一致结果

具体会议通常只启用其中一部分。准备内容一般包括环境或容器、依赖与硬件说明、运行脚本、数据来源、关键图表的生成命令、预期时间和结果容差。依赖特殊硬件时，还要按规则提供远程访问、预生成数据或可验证的替代路径。

#### 注册与现场报告

不少会议要求至少一位作者注册并完成口头报告、Poster 或 Demo。违反 no-show policy 可能影响论文集收录。注册费、差旅、签证、单位审批和报告准备都应计入时间与预算，而不是等录用后再处理。

### 5. Workshop、Poster 和 Short Paper 的位置

- **Workshop**：适合尚未成熟、希望提前获得反馈的工作。能否扩展后投正会，要查看两个载体的重复发表政策。
- **Poster**：适合展示阶段性结果和与同行密集交流；是否构成正式发表取决于是否进入论文集、是否有完整论文和 DOI。
- **Short Paper**：通常要求独立、完整但范围较小的贡献，不应简单理解为“正文没中后的保底版本”。
- **Demo / Late-breaking Results**：侧重系统演示或新近结果，后续发表边界同样需要提前确认。

接受降轨或短文邀请前，应先判断：它是否满足当前成果认定要求，是否会限制后续完整版本，以及现有贡献是否已经适合公开。

### 6. 怎么排一年的会议日历

可以先用 ccfddl.com、aideadlin.es 等工具收集日期，再回到会议官网核实。年度日历至少记录：摘要注册、正文截止、作者回应、通知和会议日期。

一个更稳妥的倒推方式：

1. 选择一个主目标，并准备一个研究社区相近、截止日晚若干月的备选
2. 在正文截止前预留完整初稿、合作者反馈、实验冻结和格式检查时间
3. 最后几天以核对论证、图表和提交材料为主，不再随意改变核心实验
4. 投稿后继续完成稳健性分析和可复现整理，但不要假定一定会进入 rebuttal 或 artifact 阶段
5. 被拒后先消化评审意见，再决定是补实验、重写定位，还是更换研究社区

会议日历的价值不是制造更多“必须赶上”的节点，而是让实验成熟度与投稿窗口相匹配。工作尚未形成完整证据链时，推迟到下一轮通常比仓促提交更合理。

## 第五部分：不同方向的发表生态不一样

“期刊高于会议”只在一部分领域成立。大致的划分：

|方向|主导载体|备注|
| ----------------------------------| --------| ------------------------|
|体系结构、操作系统、编译、数据库|会议|顶会地位明确高于高档期刊|
|机器学习、计算机视觉、自然语言处理|会议|同上，且预印本文化浓|
|网络、安全|会议为主|低于顶会时期刊价值回升|
|控制、信号处理、通信理论|期刊|会议多为交流场合|
|集成电路、固体电子|两者并重|顶会与顶刊各自有硬分量|
|材料、化学、生物、医学|期刊|会议不计入正式成果|
|数学|期刊|周期极长，一年以上常见|

不要依赖这张表。自查方法更可靠：列出本方向近三年你最佩服的十篇工作，看它们首发在哪里。它们集中出现的地方，就是你该去的地方。

### 交叉方向的困境

如果你的工作同时沉到硬件、系统与算法，会碰到一个真实的麻烦：每个社区都认为它属于另一个社区。系统会议说算法贡献不足，算法会议说工程成分过重。四条应对：

1. **选定一个主社区，按它的叙事写。** 同一份工作对系统社区要强调真实平台上的端到端收益，对算法社区要强调新的问题建模与边界条件。
2. **不要两边都想要。** 写成“既提出新算法又完成系统实现”的稿子，两个社区都会觉得不深。
3. **把另一面当证据，不当贡献。** 写给系统社区时，算法部分只需说清为何必要；反之亦然。
4. **找跨领域载体。** 一些会议与期刊本就以交叉为定位，审稿人组成更混合，对这类工作友好得多。

## 附录 A：如果你关注 AI Infra、体系结构与集成电路

这一附录按研究社区和贡献类型建立候选集，而不是给会议、期刊贴“冲、稳、保”标签。具体会议制度、CCF 分类、分区和截止日会变化，使用时应核对当年官网。

### A1. 先确定工作属于哪个社区

|社区|代表性载体示例|常见关注点|更适合的工作形态|
| --------------------| ---------------------------------------------------------------| ----------------------------------------------| ------------------------------------|
|机器学习系统|MLSys 等|真实模型负载、吞吐与时延、训练或推理效率|ML 工作负载驱动的系统设计|
|体系结构|ISCA、MICRO、HPCA、ASPLOS；IEEE TC、ACM TACO|新机制、设计空间、硬件开销、微基准与端到端收益|体系结构机制、加速器、硬件—软件协同|
|操作系统与分布式系统|OSDI、SOSP、EuroSys、USENIX ATC；IEEE TPDS、JPDC|系统抽象、正确性、容错、可扩展性和真实部署|完整系统与分布式机制|
|高性能计算|SC、HPDC、PPoPP、IPDPS、CLUSTER、ICPP|并行效率、通信开销、规模扩展和科学计算负载|并行运行时、通信优化、大规模评测|
|移动、边缘与网络|MobiCom、SenSys、ACM SEC、INFOCOM、ICDCS；IEEE TMC、IoT-J|网络与设备约束、能耗、时延、部署真实性|边缘推理、移动系统、网络协同|
|EDA 与集成电路|DAC、ICCAD、DATE、ISSCC、VLSI Symposium；IEEE TCAD、JSSC、TVLSI|工艺、面积、功耗、时序、版图或测试芯片数据|电路、芯片实现、EDA 方法与设计流程|
|云计算与服务系统|SoCC 等；FGCS、CCPE、JSA|多租户、资源管理、成本、可靠性和运营负载|云平台、调度与资源管理|

这里的名称是候选集起点，不是排名。SC、MobiCom、SoCC 等载体在各自社区有明确定位，不能因为被放在某一行就理解为难度较低。Workshop 也不是“保底版正会”，它更适合尚未成熟、希望提前获得反馈的工作。

### A2. 用贡献类型筛候选

- **提出新的体系结构机制**：先看 ISCA、MICRO、HPCA、ASPLOS 及相应体系结构期刊是否持续发表同类问题。
- **实现完整的分布式推理或训练系统**：先判断主要贡献是系统抽象、ML 工作负载效率，还是高性能通信，再分别查看系统、MLSys 或 HPC 社区。
- **研究边缘设备和受限互连**：重点证明约束真实存在，并报告端到端时延、能耗、带宽与稳定性；移动、边缘、网络和 IoT 载体往往比纯算法载体更匹配。
- **完成芯片或 EDA 工作**：仅有系统级仿真通常不足以覆盖所有载体，需要根据目标社区补充面积、功耗、时序、版图或流片数据。
- **做系统性测量**：价值来自新的可复用事实、严谨测量和可推广的结论，不必硬包装成“新算法”。

### A3. 这个方向特别值得提前做的准备

**真实硬件数据有说服力，但不是自动创新。** 真机测量能够提高可信度；要成为贡献，还需要解释为什么现有研究没有覆盖该条件，以及新约束带来了什么可推广的结论。

**非标准配置应被写成研究变量。** 带宽受限、缺少高速互连、节点异构等条件不是“设备不够好”，而是新的系统约束。论文需要给出对照实验，区分哪些结论来自该约束，哪些只是实现差异。

**测量元数据从第一天记录。** 硬件与固件、驱动和框架版本、随机种子、重复次数、方差、功耗模式、温度和网络配置都可能影响结果。

**先建立微基准，再做优化。** 单节点计算、内存带宽、节点间吞吐与时延、集合通信开销通常是解释系统瓶颈的基础，但图的顺序应服务于论证，不必机械地规定为“前三张图”。

**提前规划 artifact。** 特殊硬件会提高复现门槛，需要尽早考虑容器、脚本、远程访问、预生成数据和许可问题。

**预印本与宣传政策逐年核查。** 不能根据往年经验推断当年双盲或静默期政策。

### A4. 排一年的投稿节奏

维护两张表即可：一张是会议年度日历，另一张是期刊候选表。同一实验平台可以支撑不同研究问题，但不能把同一贡献换个叙事重复发表。每一篇稿件都应有独立的研究问题、贡献边界和新增证据。

投稿前至少确认三件制度问题：

1. 本单位是否认会议成果，以及如何使用 CCF 或其他目录
2. 联合培养、联合实验室或企业合作中的署名单位和成果归属
3. 代码、数据、模型和硬件信息的开源是否需要审批

这些问题可能反向决定目标载体和时间表，应在实验基本成形前处理。

## 附录 B：术语表

投稿流程里高频出现、但没人会特意解释的词。

**审稿与决定**

- **desk reject**：未送外审，编辑直接退稿。没有审稿意见，因此不携带任何关于论文质量的信息。
- **Under Review**：审稿人已接受邀请并在审阅。
- **Required Reviews Completed**：意见已收齐，编辑待汇总。这个状态后通常一到两周内出结果。
- **Major / Minor Revision**：大修需补实验或重构论述，一般一到三个月期限；小修多为写作与图表，一到四周。拿到大修通常意味着已过半。
- **Reject and Resubmit**：形式上拒稿，实质上邀请实质修改后重投。重投成功率高于全新投稿。
- **Transfer**：编辑建议把稿子转到同出版商旗下另一本刊，审稿意见一同转去，可省一轮周期。接受前先查目标刊的分区与 APC。
- **rebuttal**：会议审稿意见释出后，作者的一次书面回应机会。窗口常为三到七天，有严格篇幅限制，不能提交新版稿件。详见第四部分。
- **response letter**：期刊修改阶段的逐条回应信。与 rebuttal 不同的是它篇幅不限，且伴随真实的稿件修改。
- **meta-review**：领域主席在程序委员会讨论后写的总结意见，优先级高于单个审稿意见。
- **PC / TPC / AC**：程序委员会、技术程序委员会、领域主席。实际承担审稿与录用决策的人。
- **score 与 confidence**：审稿人的推荐分与自评信心度。评分需要结合评审理由和信心度阅读；可澄清的关键误解最值得优先回应。
- **shepherding**：录用后指定一位审稿人监督你完成必改项，未完成可能被撑回。

**流程与产出**

- **abstract registration deadline**：摘要注册截止日，通常比正文截止早一周。错过就不能投正文。
- **camera-ready**：录用后提交的最终排版稿，不能再改内容主体。
- **artifact evaluation**：可复现包审查。提交代码、数据与脚本，由审查员尝试复现，通过后获得相应徽章。
- **double-blind**：双盲评审。作者与审稿人互不知情，需匿名化稿件与代码链接。
- **preprint**：预印本。未经同行评审就公开的稿件（如 arXiv）。注意目标会议的预印本窗口规则。
- **Cover Letter**：投稿时给编辑的信。作用是说清为何适合本刊、新意何在、以及申明未一稿多投。
- **CRediT**：一套标准化的作者贡献分类体系，越来越多刊物强制要求填写。

**计量与费用**

- **APC**：文章处理费，开放获取刊向作者收取。典型一千五到四千美元，高影响力刊可超六千。投稿前必须确认经费渠道。
- **超页费**（over-length / page charge）：超出免费页数后每页收费，IEEE 系列常在每页一百多到三百美元区间。
- **SCI / SCIE**：索引数据库，不是等级。被收录只说明在库内。
- **EI**：工程文献索引，兼收期刊与会议；与 SCIE 的覆盖对象不同，不宜简单换算高低。
- **CCF 推荐目录**：中国计算机学会的分类目录，不是索引。在计算机领域，CCF-A 会议的分量常高于大多数 SCI 刊。
- **影响因子**：前两年论文在当年被引总数除以前两年可引论文数。均值受长尾与综述影响很大，不代表单篇水平。

## 附录 C：三份可直接用的表

### C1. 候选载体评估表

每个候选一行：名称 / 类型（刊或会）/ 分区或 CCF 等级 / 本校认定 / 方向命中参考文献数 / 估计录用概率 / 估计周期或截止日 / 费用 / 是否通过硬约束 / 备注。

先筛硬约束一列，不过的直接删行，不要留着纠结。

### C2. 投稿记录表

每次投稿一行：目标 / 投稿日 / 各状态切换日 / 结果 / 审稿意见要点 / 已回应项 / **未回应项与原因** / 下一步。

倒数第二列最重要。改投前必须逐行看一遍：审稿人池重叠，没回应的意见极可能下一家又碰上。

### C3. 投稿前清单

硬约束

- [ ] 本校与学院毕业要求确认过（含分区、作者位次、单位归属、共一认定）
- [ ] 目标载体当前收录状态已在 Master Journal List 核过
- [ ] 不在任何预警名单
- [ ] 时间倒推后仍留有余量（包含录用到见刊的滞后）
- [ ] 费用渠道已落实

内容

- [ ] 参考文献命中目标载体至少三篇
- [ ] 目标载体近两年目录看过，确认方向匹配
- [ ] 贡献陈述与该载体审稿人关心的东西对得上
- [ ] 模板、页限、图表规范、参考文献格式全部改过
- [ ] Cover Letter 已写，且针对这本刊
- [ ] 若为会议扩展稿，已声明出处并说明新增部分
- [ ] 若双盲，作者信息、致谢、基金号和代码链接已完成匿名化处理
- [ ] 查重已跑过
- [ ] AI 工具使用按要求披露

预备

- [ ] 已列出三到五个最可能被质疑的点，并安排了对应补充实验
- [ ] 实验脚本与环境可重复执行，为可复现包做好准备
- [ ] 下一个候选载体已选定（不是被拒后再想）

## 本文的框架

```
三个基本判断
  逐层淘汰，不是打分排序
  选刊在立项时就开始
  选刊就是选审稿人

四层过滤
  硬约束 → 时间预算 → 质量匹配 → 成本与偏好

期刊：投递顺序按期望时间成本排，不按档次
会议：从截止日倒推，rebuttal 的准备在投稿前
```

选刊不是一个需要灵感的问题。把约束列完，往往只剩三两个选项，剩下的只是把它们排个序。花一下午把约束列清，能省下很多个月。
