## 一、OPD 是什么？—— 后训练阶段的一种策略蒸馏技术

**On-Policy Distillation (OPD)** 是大语言模型后训练阶段的一项策略蒸馏技术。其核心特点是：在训练过程中，让学生模型（Student）用自己的当前策略实时生成数据（On-Policy），再由教师模型（Teacher）对这些实时生成的数据提供**稠密的 token 级别监督**，从而高效地将教师模型的能力迁移给学生模型。

### 1.1 与其他后训练方法的对比

为了更清晰地理解 OPD 的定位，可以将其与常见的后训练方法进行对比：

| 方法 | 数据来源 | 监督信号 | 核心特点 |
|------|----------|----------|----------|
| **OPD** | 学生模型实时生成（On-Policy） | 教师模型提供的 token 级稠密信号 | 解决训练与推理分布不匹配问题，效率高，但对稳定性敏感 |
| **SFT** | 静态的、预先收集的数据集（Off-Policy） | 数据集中固定的离散标签 | 方式简单直接，但容易让学生模型只是"模仿"，且存在分布漂移风险 |
| **RL** | 学生模型与环境的交互 | 稀疏的、任务层面的奖励信号（如最终答案对错） | 有助于探索，但信号稀疏，优化难度大，容易出现"奖励破解" |

### 1.2 核心优势：解决分布不匹配

传统离线蒸馏使用静态数据训练，但学生模型在推理时生成的分布可能与训练数据不同。OPD 通过让学生模型"边学边练"，使其在动态交互中更好地适应自己的生成风格，从根本上解决了训练与推理时的分布不匹配问题。

其高效运作依赖于三个核心机制：

- **稠密监督**：教师模型在学生生成的每一个 token 上都提供指导，比传统的序列级最终答案（稀疏奖励）信号更密集，学习效率更高。
- **"前瞻性"更新**：OPD 能在训练初期就建立起朝向最终模型的稳定更新轨迹，在参数更新方向上具有更强的低秩集中性。
- **策略统一**：可将多个擅长不同任务的"专家模型"的能力整合到一个通用的学生模型中。

## 二、OPD 的四大核心法则

### 法则一：思维模式对齐决定蒸馏上限

研究者发现，**师生之间底层生成习惯的相似性（Overlap Ratio）决定了蒸馏的上限**，而非教师的绝对能力。

#### 关键实验：Base 模型向不同教师学习

研究者让弱 Base 模型 Qwen3-1.7B-Base 向两个能力相近的教师学习：一个是 Qwen3-4B（Non-thinking），另一个是仅经过 GRPO 训练的 Qwen3-4B-Base-GRPO。结果发现：

- **Base 学生 + GRPO 教师**：由于学生也是 Base 模型，它与经过 GRPO 强化的 Base Teacher 的思维模式更近（初始 Overlap Ratio 更高），最终蒸馏效果显著提升。
- **Base 学生 + Non-thinking 教师**：Non-thinking Teacher 输出简洁直接，而 Base 学生倾向于输出冗余续写，两者思维模式差异大，蒸馏效果差。

**核心启示**：如果早期思维模式错配，后续很难完全弥补。师生"同频"比教师"更强"更重要。

#### 相关术语解释

- **Base 模型**：完成预训练但未经过任何后训练的原始模型，掌握通用语言知识但缺乏指令遵循和结构化推理能力。
- **Thinking Pattern（思维模式）**：模型生成文本时的内部概率分布和 Token 序列的统计特征，包括推理链风格、词汇选择习惯等。
- **GRPO（Group Relative Policy Optimization）**：一种强化学习算法，通过让模型生成多个回答并互相比较好坏来更新权重，使模型学会生成更符合奖励信号的回答。
- **Overlap Ratio（重叠率）**：给定相同提示，比较学生和教师在每个位置预测的 Token 概率分布的重合程度，反映两者思维模式的相似性。

### 法则二：高分 ≠ 新知识

如果师生思维模式一致，且教师分数更高，蒸馏就一定管用吗？答案是否定的。

#### 关键实验：同 Pipeline 教师 vs RL 后训练教师

研究者在 DeepSeek 和 Qwen 两个模型家族中都观察到同样的现象：

| 模型家族 | 教师类型 | Gap Recovery | 解读 |
|----------|----------|-------------|------|
| DeepSeek | 同 Pipeline 大模型（仅参数量更大） | 5.3% | 几乎没学到新东西 |
| DeepSeek | RL 后训练模型 | 16.9% | 学到了显著的推理能力 |
| Qwen | 同 Pipeline 大模型 | 15.6% | 有一定提升，但仍然有限 |
| Qwen | RL 后训练模型 | 58.6% | 获得了质的飞跃 |

**核心洞察**：同 Pipeline 下更大的教师，在学生眼中只是"同一类分布的不同尺度版本"，并不会提供多少新的可迁移信号。而经过 RL 后训练的教师带来了结构性的新知识——新的解题路径、更丰富的中间状态、不同的概率分布。

#### 关键实验：反向蒸馏的震撼结论

研究者做了一个更极端的实验：用 RL 后的 JustRL-1.5B 做学生，让它反过来向自己 RL 之前的 checkpoint R1-Distill-1.5B 学习；同时拿一个更大、分数也更高的同家族 R1-Distill-7B 做对照。

**结果**：向 7B 学习和向 1.5B 学习，效果几乎一样——都让学生的能力倒退回了前 RL 的水平。

这说明 7B 虽然分数高，但相较于 1.5B 只是参数规模带来的红利，并没有提供更多可学习的信息。**OPD 不是在简单地"学习高分"，而是在主动提取并复刻教师的思维模式。**

#### 术语解释

- **Gap Recovery（差距恢复）**：衡量蒸馏效果的指标，计算公式为 (学生蒸馏后性能 - 学生初始性能) / (教师性能 - 学生初始性能) × 100%。
- **Pipeline / Recipe**：训练或蒸馏模型时采用的完整方法，包括数据、算法、超参数等。
- **Teacher-Student Gap**：学生模型与教师模型在特定任务上的性能差距。

### 法则三：成功的蒸馏是"双向奔赴"

研究者监控了训练全过程的动态指标，发现了一个极为清晰的规律：成功的 OPD 是一场高概率 Token 的"双向奔赴"。

#### 成功 vs 失败的动态模式

| 指标 | 成功 OPD | 失败 OPD |
|------|----------|----------|
| **Overlap Ratio** | 从 72% 稳步攀升到 91% 以上 | 从头到尾基本无变化 |
| **Entropy Gap** | 迅速缩小 | 从头到尾基本无变化 |

#### Entropy Gap 的含义

**Entropy Gap = 学生熵 - 教师熵**，衡量两者预测不确定性的差异：

- **正值**：学生比教师更不确定（更"迷茫"）
- **负值**：学生比教师更确定（更"武断"）
- **零**：两者的不确定性水平一致

在成功蒸馏中，学生变得更确定（熵下降），教师也变得更灵活（熵略微上升），最终两者在"适度确定"的水平上达成一致。这不是单向模仿，而是师生在对话中互相适应、协同进化。

#### "双向奔赴"的本质

很多人以为 OPD 只是学生在单向模仿教师，但熵的变化揭示了教师也在变化。在 OPD 的动态交互闭环中，学生生成的 Token 序列直接成为教师下一轮推理的上下文。因此，学生的思维模式会实时塑造教师的回答风格。研究者观测到的，正是这个协同进化过程——师生在对话中互相适应，最终达成"重叠率上升、熵差距缩小"的共识状态。

### 法则四：重叠区域即是全部

研究者把蒸馏目标拆开，做了一组剥离实验，发现了一个极具颠覆性的结论：**那些被师生共同看好的高概率 Token 是整个优化的核心引擎**，贡献了主要梯度和优势。如果只对这些 Overlap Token 计算损失，蒸馏性能几乎不打折扣；而那些非重叠的 Token 对优化几乎毫无贡献。

#### 剥离实验结果

| 实验设置 | 包含的 Token | 结果 |
|----------|-------------|------|
| 完整 OPD | 所有 Token（重叠 + 非重叠） | 性能基准 100% |
| 仅重叠 Token | 师生 Top-K 都预测的高概率 Token | 性能 ≈ 完整 OPD（几乎无损失） |
| 仅非重叠 Token | 师生意见不一致的 Token | 性能极差（甚至为负） |
| 强制学习非重叠 | 让学生模仿教师独断的 Token | 性能显著下降 |

#### 深层含义

- **重叠 Token 代表了"可达的认知边界"**：即学生"踮踮脚能够到"的知识，这是维果茨基"最近发展区"理论在 LLM 蒸馏中的完美体现。
- **可蒸馏知识 = 师生当前能力圈的交集**：即使教师是全知的，也只能教给学生"学生本来就能理解的那部分"。
- **OPD 的本质是"共识强化"而非"知识迁移"**：不是教学生不会的，而是把师生都会的打磨到极致。

## 三、处方篇：两招拯救"无可救药"的蒸馏

如果手头只有思维模式不契合的教师，是否就束手无策了？研究者给出了两剂"对症下药"的药方。

### 药方一：Off-Policy 冷启动（Cold Start）

**问题**：直接做 On-Policy 蒸馏时，初始 Overlap 太低，师生"鸡同鸭讲"。

**方案**：在 OPD 之前，先让学生在教师生成的 rollout 上进行一轮轻量级的 SFT。

**逻辑链**：

```
初始状态：Overlap = 50%，Entropy Gap = +0.5
    ↓ SFT 热身（约 1000 步）
冷启动后：Overlap = 72%，Entropy Gap = +0.2
    ↓ 切换为 OPD
最终：Overlap = 91%，Entropy Gap ≈ 0
```

**核心机制**：先"搭桥"再"过河"。SFT 建立学生和教师之间的基本连接，让学生学会"大概应该这样说话"，避免在完全混乱的状态下开始 OPD。

**注意事项**：
- 冷启动步数需适中（约 1000 步），太少效果不明显，太多可能过拟合到 Off-Policy 分布。
- Prompt 需覆盖教师擅长的各个领域，避免在单一类型数据上过拟合。

### 药方二：教师对齐的提示词（Teacher-aligned Prompts）

**问题**：如果 OPD 时给的 prompt 偏离教师训练分布，教师会"水土不服"，输出质量下降。

**方案**：让 OPD 过程中喂给模型的提示词更贴近教师模型在后训练阶段所见过的数据分布，包括**模板层面的对齐**和**内容层面的对齐**。

**两层对齐**：

1. **模板对齐（Format Alignment）**：使用教师训练时的标准模板格式。例如，如果教师习惯"问题：{q}\n请一步步推理："，OPD 时也应采用此格式。
2. **内容对齐（Content Alignment）**：按教师擅长的领域分布采样 prompt，如数学题 40%、代码题 30%、逻辑推理 20% 等。

**混合 OOD 策略**：

完全对齐虽然能加速收敛，但会导致学生熵降得太快，引发**熵坍塌（Entropy Collapse）**——模型变得过度自信，失去探索能力和泛化能力。

解决方案是混合使用 OOD（Out-Of-Distribution，分布外）prompt：

| 场景 | 对齐 : OOD | 理由 |
|------|-----------|------|
| 追求领域内 SOTA | 90 : 10 | 高风险高回报 |
| 通用部署（推荐） | 70 : 30 | 平衡性能和泛化 |
| 防止过拟合 | 50 : 50 | 更鲁棒，但收敛慢 |

**OOD 的作用**：给学生"刹车"，防止熵降太快，保持模型的泛化能力，让学生学会"什么时候该确定，什么时候该犹豫"。

## 四、OPD 的应用边界与 Scaling 瓶颈

### 4.1 当前 OPD 的主战场

由于存在长轨迹熵崩塌的问题，当前 OPD 主要应用于中短长度的任务：

| 应用场景 | 轨迹长度 | OPD 效果 | 具体说明 |
|----------|----------|----------|----------|
| 数学推理 | 中等（数百 token） | ✅ 最佳 | 8B 模型在 AIME'24 上从 60% 提升到 70%，计算成本比 SFT 低 9-30 倍 |
| 代码生成与修复 | 中等 | ✅ 高效 | 可在学生自己生成的代码轨迹上逐 token 打分 |
| 指令遵循（IF） | 短（数十到数百 token） | ✅ 优秀 | 可恢复因学习新知识而损失的指令遵循能力 |
| 个性化/风格对齐 | 短到中等 | ✅ 有效 | 特定语气、格式、工具使用等行为 |
| 多轮 Agent 交互 | 长（累积数千 token） | ❌ 原始 OPD 翻车 | 原始 OPD 在多轮场景下 KL 散度持续飙升 |

### 4.2 长轨迹场景的"从后向前的熵崩塌"

在长达 15K token 的响应中，研究者观察到了清晰的**"从后向前的熵崩塌"**：

```
轨迹深度 →

0        5K       10K      15K
|--------|--------|--------|
✅ 正常   ⚠️ 预警   ❌ 噪声   💀 崩溃
熵低      熵上升    熵高      完全随机
Overlap高  下降    极低      无意义
```

**机理**：随着生成的深入，学生的前缀越来越偏离教师熟悉的分布，导致教师在后半段给出的奖励变成了纯粹的噪音，进而引发整个训练的坍塌。

**核心矛盾**：密集监督与监督可靠性之间存在根本性张力。想要每个 token 都有反馈（密集），但这些信号在长轨迹后半段可能变成噪声（不可靠），两者无法同时满足。

### 4.3 全局有用 ≠ 局部可优化

另一个微妙但重要的发现：失败教师给出的全局 reward 其实并不弱，区分正确/错误 rollout 的 AUROC 甚至和成功教师相近。这说明失败不是因为 reward 信号本身没有信息量，而是因为**reward 的局部优化几何结构出了问题**——全局有信息，局部却平坦。

形象理解：教师像个阅卷老师，能判断整篇作文是 80 分还是 60 分（全局 OK），但无法告诉学生每个字该怎么写（局部失效）。学生知道"我错了"，但不知道"哪里错、怎么改"，无法有效更新参数。

### 4.4 解决方案：TCOD

2026 年 5 月，香港中文大学联合阿里通义团队提出了 **TCOD（Temporal Curriculum On-Policy Distillation）**，用课程学习的思路——让学生从短轨迹开始、逐步学习完整的长轨迹。

效果：Qwen3-1.7B 的原始 OPD 平均成功率仅 0.17%（完全崩溃）→ TCOD 后提升至 18% 以上；Qwen2.5-3B 从 60.45% 提升到 79.19%，训练时间还减少了 32%。

## 五、OPD 的工程挑战与解决方案

### 5.1 挑战一：训练不稳定

**问题本质**：梯度方差过大。学生生成的每个 token 序列具有高度随机性，同一 prompt 可能生成完全不同的轨迹，导致梯度方向上下剧烈波动。

**解决方案**：
- **vOPD（控制变量基线）**：引入一个"基线"来减掉梯度中的随机波动部分。估算学生当前的"平均表现"，用实际梯度减去平均值，保留"真正值得学习的信号"。
- **VETO（自适应目标重塑）**：实时判断当前 Teacher 监督信号是否真正有益。如果发现某个梯度可能把学生推向错误方向，就"一票否决"，不让它参与参数更新。

### 5.2 挑战二：监督信号不可靠

**问题本质**：Teacher 也会"不懂装懂"。在长轨迹或 OOD 数据上，Teacher 看到的上下文可能完全陌生，给出的 token 概率分布其实是瞎猜的。

**解决方案**：
- **Top-K 局部支持匹配**：只有当 Teacher 对 Top-K 候选 token 的置信度很高（如 Top-1 概率超过 0.7）时才允许指导；如果概率分布平坦，说明 Teacher 自己也没把握，不如"闭嘴"。
- **Top-p 采样**：动态选择累计概率达到 p（如 0.9）的 token 集合，确保 Teacher 只在自己擅长的子集上提供监督。

### 5.3 挑战三：基础设施开销大

**问题本质**：实时运行大模型 Teacher 成本极高。Teacher 往往比 Student 大很多倍，需要以同样频率参与训练循环。

**解决方案**：**Lightning OPD**。提前计算并存储 Teacher 在大量输入上的输出概率分布，Student 训练时直接读取预存储结果，无需实时调用 Teacher。实现约 4 倍的加速。

### 5.4 挑战四：教师与学生能力不匹配

**问题本质**："兔子教乌龟游泳"——思维模式不同频，强行蒸馏导致学生始终无法理解教师的"思考方式"。

**解决方案**：
- **选用同家族模型**：同系列模型在 tokenizer、预训练数据分布甚至思维模式上天然更接近。
- **教师对齐提示选择**：主动调整提问方式，让问题落在 Teacher 和 Student 都能理解的"交集"内。

## 六、OPD 在 LLM 后训练中的定位

### 6.1 后训练会改变权重吗？

是的。无论是 SFT、RLHF、DPO 还是 OPD，后训练技术都会通过反向传播和梯度下降更新模型的权重参数。

| 维度 | 预训练 | 后训练 |
|------|--------|--------|
| 主要目标 | 学习语言、事实、推理的通用分布 | 学习特定的任务、风格或偏好 |
| 权重变化幅度 | 从随机初始化到收敛，变化极大 | 在预训练权重基础上微调，变化相对较小 |
| 潜在风险 | 过拟合风险较低 | 灾难性遗忘：过度后训练可能破坏预训练学到的通用知识 |

不同后训练技术的差异在于改变权重的方式和侧重点：SFT 让权重朝着"模仿"标准答案的方向更新；RLHF/DPO/OPD 让权重朝着"生成更被偏好"的输出的方向更新。

### 6.2 标准后训练三阶段流程

当前 LLM 后训练通常采用多阶段组合流程，OPD 并非替代其他方法，而是作为补充工具：

```
预训练模型（Base Model）
        ↓
┌───────────────────────────────────────┐
│  阶段1：SFT（监督微调）                │
│  - 用 10-100 万条指令-回复对           │
│  - 教会模型"听懂指令、对话格式"         │
└───────────────────────────────────────┘
        ↓
┌───────────────────────────────────────┐
│  阶段2：偏好对齐（DPO/SimPO/KTO 等）    │
│  - 用人类偏好数据优化"什么是更好回答"    │
└───────────────────────────────────────┘
        ↓
┌───────────────────────────────────────┐
│  阶段3：强化学习（GRPO/DAPO/RLVR 等）   │
│  - 在数学、代码等可验证任务上探索推理策略 │
└───────────────────────────────────────┘
        ↓
    OPD 补充：能力蒸馏 / 能力恢复 / 个性化
```

### 6.3 各方法的擅长与不擅长

| 方法 | 擅长什么 | 不擅长什么 |
|------|----------|------------|
| SFT | 教会格式、基础行为 | 超越数据分布 |
| DPO/偏好对齐 | 安全、价值观、风格 | 提升推理能力 |
| RLVR/GRPO | 推理、探索、泛化 | 稳定性、成本 |
| OPD | 高效蒸馏、能力恢复 | 长轨迹、多轮（需 TCOD 辅助） |

**结论**：没有单一方法能包打天下。后训练是一个工具箱，需要根据目标选择合适的工具组合。

---

## 七、总结

OPD 是一种强大的后训练技术，特别适合用于提升大模型的推理能力（如数学、代码）以及进行多专家能力融合。它通过"在动态交互中学习"的方式，比传统的 SFT 和 RL 方法更高效。

### 核心要点回顾

1. **思维模式对齐 > 绝对能力**：师生"同频"比教师"更强"更重要。
2. **高分 ≠ 新知识**：RL 后训练的教师比同 Pipeline 的大模型更能带来"认知跃迁"。
3. **双向奔赴**：成功的蒸馏是师生在认知层面的协同进化，而非单向模仿。
4. **重叠区域即是全部**：可蒸馏知识仅限于师生能力圈的交集。
5. **Scaling 有瓶颈**：长轨迹场景存在"从后向前的熵崩塌"，需借助 TCOD 等课程学习策略。
6. **工程挑战可解**：vOPD、VETO、Top-K/Top-p、Lightning OPD 等技术可有效应对稳定性、可靠性、开销和匹配问题。
